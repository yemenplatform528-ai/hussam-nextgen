# تدقيق استقلالية المشاريع — سجل الحقيقة وخطة الفصل

**تاريخ التدقيق:** 2026-10-22  
**الغرض:** تحويل قرار استقلال المشاريع إلى مسار قابل للتحقق، دون نقل أو حذف أو إعادة نشر أي مشروع في هذه المرحلة.

## 1. حدود هذا التدقيق

هذا تدقيق مكتبي محدود بمصدرين من GitHub وبيئة العمل المتاحة، وليس جردًا كاملًا لكل حسابات الاستضافة أو قواعد البيانات أو الأجهزة.

- `main` وقت التدقيق: `2caa70c662ff08e30e46e771df9c2ef65307c54e`.
- فرع مراجعة الحسام الأمني: `security/hussam-ai-auth-hardening-followup`، والالتزام المرصود `79884607b7c4a1f33044333895bbff49fa14ea6e`.
- قائمة المستودعات التي أعادتها وصلة GitHub المتاحة لهذا الحساب أظهرت `yemenplatform528-ai/hussam-nextgen` فقط. هذا يثبت نطاق ما أتاحته الوصلة، ولا يثبت عدم وجود مستودعات أخرى خارج هذا النطاق.
- لم تُقرأ هنا لوحات Render أو Tiniest أو Neon أو إعدادات الأسرار؛ لذلك لا تُعد حالة أي خدمة أو قاعدة بيانات أو مفتاح اعتماد متحققة بهذا المستند.

## 2. الأدلة المرصودة

### أ. توجّه المستودع الرئيسي

يعرّف `README.md` في `main` المستودع بأنه `Hussam NextGen Unified Platform` ويصفه بأنه منصة موحدة مستمرة تشمل التجارة والشبكة والذكاء الاصطناعي وHUS، ويذكر صراحة أن التطوير يجري كمنصة واحدة. ويعرض `docs/ARCHITECTURE.md` حدودًا داخلية بين المجالات والمحركات والنواة، لا حدودًا مستقلة بين المنتجات.

**الحالة:** `VERIFIED` — هذا هو النص الموجود في الملفات المقروءة، وليس إثباتًا بأن كل الوظائف منشورة أو تعمل.

### ب. ملفات ومسارات ظهرت في فرع العمل الأمني

في فرع `security/hussam-ai-auth-hardening-followup` ظهرت المسارات التالية داخل المستودع نفسه:

- `hussam-ai-backend/` — جسر استدلال ومصادقة للحسام AI.
- `hussam-ai-portal/` — واجهة مستقلة للحسام AI، وبداخلها مساحة `notion-analyst-assistant`.
- `yib-world-independent/` — تطبيق YIB/WORLD.
- `app/`, `tests/`, `alembic/`, `docs/` — تطبيق المنصة الموحدة ومكوناتها.

**الحالة:** `OBSERVED` — وجود المسارات مثبت في شجرة ذلك الفرع. وجود مجلد لا يثبت استقلال النشر أو البيانات أو الاعتمادات.

### ج. مشاريع لم يثبت موقعها المستقل في هذا التدقيق

- شبكة التجارة اليمنية كمستودع وبيئة نشر مستقلين: `UNKNOWN`.
- مشروع الإنترنت كبنية وخدمة مستقلة: `UNKNOWN`.
- جميع النسخ الاحتياطية والبيانات والذاكرة وملكية الحسابات ومفاتيح النشر: `UNKNOWN` حتى فحص كل مصدر فعليًا.

`UNKNOWN` لا تعني أن المشروع غير موجود؛ تعني أن الأدلة الحالية لا تكفي لتأكيد موقعه وحدوده وملكيته التشغيلية.

## 3. القرار المعماري المقترح

يجب التعامل مع المشاريع كمنتجات مستقلة، لا باعتبارها مجلدات مستقلة داخل مستودع مشترك فقط:

1. **Hussam NextGen / Yemenization:** منصة التجارة والخدمات اليمنية، بحدود المجالات والنواة والبيانات الخاصة بها.
2. **Hussam AI:** مساعد حي مستقل؛ واجهته وجسر الاستدلال وذاكرته وإعدادات مزوده قابلة للتبديل والاسترداد بصورة مستقلة.
3. **YIB / WORLD:** جسر استخبارات واستمرارية وتشغيل، له سجل حقيقة وذاكرة وعقود استرداد منفصلة.
4. **شبكة التجارة اليمنية:** مشروع مستقل إذا أكّد الجرد أنه منتج منفصل عن منصة Hussam NextGen؛ لا يُنشأ ازدواج وظيفي قبل حسم الحد بينهما.
5. **مشروع الإنترنت:** مسار مستقل للدراسة والبنية والاتصال والتكاليف، ولا يُعامل كميزة برمجية داخل المنصة التجارية.

هذه حدود مستهدفة، وليست شهادة بأن الفصل قد تم.

## 4. قواعد الفصل الآمن

- لا يُنقل مستودع أو يُحذف فرع أو خدمة أو قاعدة بيانات قبل حفظ نقطة استرداد قابلة للقراءة والتحقق.
- لا يُنسخ أي سر إلى Git أو مستندات أو سجلات. تُسجل أسماء متغيرات الإعداد فقط، لا قيمها.
- لكل مشروع: مستودع أو مصدر حقيقة محدد، مالك واضح، بيئة تطوير واختبار وإنتاج، قائمة اعتماديات، سياسة بيانات ونسخ احتياطية، وخطة استعادة مستقلة.
- يمكن مشاركة عقود أو مكتبات صغيرة بإصدارات واضحة؛ لا مشاركة ضمنية للأسرار أو قواعد البيانات أو دورة النشر.
- لا يُفصل الكود اعتمادًا على أسماء المجلدات فقط. يجب أولًا رسم imports، وعمليات CI/CD، ومراجع قواعد البيانات، وأسرار البيئة، وروابط النشر، ومسارات الذاكرة.
- لا دمج ولا نشر إنتاجي ولا تفعيل فوترة كجزء من هذا التدقيق.

## 5. مراحل الإغلاق

| المرحلة | دليل الإغلاق المطلوب | الحالة |
|---|---|---|
| جرد المستودعات والفروع | قائمة مقروءة لكل مستودع وفرع ومالك ومصدر الحقيقة | `IN_PROGRESS` |
| جرد الاستضافة | الخدمة، المستودع/الفرع، الالتزام، عنوان الصحة، إعدادات النشر غير السرية | `BLOCKED` — يلزم فحص لوحات الاستضافة الفعلية |
| جرد البيانات والذاكرة | قاعدة البيانات، مالكها، سياسة التصدير، اختبار استعادة | `UNKNOWN` |
| خريطة الاعتماديات | مخطط الاعتماديات الداخلية والخارجية لكل مشروع | `IN_PROGRESS` |
| خطة الفصل | ترتيب نقل قابل للتراجع لكل مشروع مع نقطة استرداد | `WAITING_FOR_INVENTORY` |
| تحقق الاستقلالية | تشغيل واستعادة مشروع واحد بمعزل عن الآخر | `NOT_TESTED` |

## 6. بوابة قبول الاستقلالية

لا يُعلن المشروع مستقلًا إلا بعد تحقق جميع ما ينطبق عليه:

- يمكن تحديد مصدر الكود المعتمد واستنساخه دون الاعتماد على مساحة تطوير واحدة.
- إعدادات النشر والأسرار مملوكة وقابلة للتدوير دون كشفها.
- البيانات والذاكرة قابلة للتصدير والاستعادة، وقد جُرّبت الاستعادة فعليًا.
- يمكن تشغيل المشروع أو نقله إلى بيئة بديلة موثقة، مع بيان أي اعتماد خارجي لا يمكن الاستغناء عنه.
- فشل مشروع لا يؤدي تلقائيًا إلى تعطيل مشروع آخر بسبب سر أو قاعدة بيانات أو دورة نشر مشتركة.
- جميع النتائج مسجلة مع الالتزام والتوقيت والدليل، وتصنيف الحقيقة `VERIFIED` أو `OBSERVED` أو `BLOCKED` أو `UNKNOWN`.

## 7. الخطوة التالية ذات الأولوية

إكمال الجرد للفرع النشط ثم ربط كل خدمة منشورة بمستودعها وفرعها والتزامها، مع مراجعة قواعد البيانات والذاكرة ونسخ الاسترداد. بعد ذلك فقط تُعتمد خطة نقل تدريجية. هذا المستند لا يغير التطبيق ولا ينقل أي أصل.
