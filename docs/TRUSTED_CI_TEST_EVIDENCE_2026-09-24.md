# Trusted CI Test Evidence — 2026-09-24

## Purpose

The Developer Platform already requires test evidence to be source-bound. This document closes the missing CI provenance layer for repository-level engineering evidence.

The CI workflow now:

1. checks out the exact commit under test;
2. runs the existing baseline, compile, pytest, migration, dependency and security gates;
3. generates a deterministic source-manifest hash from Git-tracked files;
4. records the exact repository, commit SHA, workflow, run ID, run attempt and event;
5. writes the evidence as an immutable workflow artifact;
6. publishes a GitHub artifact provenance attestation for that evidence artifact.

The evidence is therefore tied to an independently identifiable CI run and commit rather than a developer-entered test status.

## Evidence schema

The generated evidence contains:

- schema_version
- evidence_type=trusted_ci_test_evidence
- repository
- workflow
- run_id
- run_attempt
- commit_sha
- ref
- event
- status=passed
- source_manifest_hash
- tracked_file_count

The artifact itself is also hashed and printed by the generator.

## Important authority boundary

This is repository-level trusted CI evidence. It does not automatically become a valid DeveloperExtensionVersion.test_source_hash.

An extension must still have an explicitly defined source artifact and source hash. The Developer Platform must bind its test evidence to that exact source artifact. The new CI evidence can serve as independently verifiable provenance for the test run, but it must not silently substitute a repository commit or repository-wide manifest for an extension source hash.

## Fail-closed rule

A future promotion integration should require all of:

- exact source artifact identity;
- exact source hash;
- trusted CI run identity;
- successful CI conclusion;
- evidence artifact hash;
- provenance/attestation verification;
- evidence generated by the same source revision;
- reviewer/approval policy where required.

No public documentation, manually supplied status, screenshot or copied run ID is sufficient.

## Result

This change closes the architectural gap between source → test result → developer-submitted evidence and the stronger production boundary: source artifact → exact CI run → immutable evidence artifact → verifiable provenance → promotion.

It does not claim production certification or close G01–G10.
